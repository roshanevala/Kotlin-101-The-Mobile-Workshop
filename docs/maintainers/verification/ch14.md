## UI contracts and test synchronization

The 18 new Activity scenarios cover initial state, selection, independent draft/committed values, selected-only save, trimming, Cancel, same-row selection, switching policy, completion/reversal, blank/length boundaries, saved rows/selection/unsaved draft, notice expiration/restart/clearing, duplicate topics, and non-replayed transient feedback. Four isolated editor checks cover incoming parent values, forwarded edit events, disabled Save with usable Cancel, and actions occurring only on events. One notice check also asserts polite live-region semantics.

Text assertions match `EditableText` separately from labels/supporting text. The controlled test host echoes edited values back to its child. A non-echoing constant host can legitimately receive blur feedback containing its original value, so it was not used to assert a universal one-event contract.

Focused input is established before replacement, with a focused-state assertion and idle synchronization. Accepted replacements are checked before later owner events. Two affected Save/Cancel scenarios also check the exact draft after scrolling Save into view, without refocusing the editor. The initial focus-separated pair passed five consecutive selected runs, and the strengthened full suite passed afterward. No replacement retry, arbitrary sleep, or weaker final committed-row assertion was introduced.

Notice checks drive the Compose test clock and rendering frames. They check before/after the delay and cross the first save's deadline after a second save. They do not claim an exact wall-clock display instant or reuse Chapter 12's TestScope clock as if it were the same API.
