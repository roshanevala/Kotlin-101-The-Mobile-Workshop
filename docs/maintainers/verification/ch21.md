## Framework boundary

- The generated header exposes `plan(topic:minutes:)` with a nullable topic, a 32-bit duration, and a nullable session. The Swift tests used a recording Swift implementation of the exported Kotlin ID protocol. The default adapter also produced a UUID through the platform factory.
- A blank receipt ID threw a declared Kotlin exception that Swift handled. Both confirmation and explicit cancellation worked when the decision arrived before the wait. For in-flight cancellation, a second waiter registered through the Objective-C completion handler. Cancelling the Swift task caused that waiter to receive an error from Kotlin. Changing just the handler to confirm the Kotlin request in a disposable copy made the assertion fail.
- Editing only the Kotlin fallback string in a disposable copy caused the next incremental Xcode build to relink the app, even though the public header was unchanged.
- The reference app linked in Release for the arm64 simulator and in Debug for a generic arm64 iOS device SDK with signing disabled. Runtime verification covered the iOS 26.5 simulator. Physical-device execution and the minimum runtime remain unverified.
