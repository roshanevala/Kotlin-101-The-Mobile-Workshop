## Learner and reference runs

Commands start in `mobile`. The [workshop](../../../chapters/20-shared-boundaries/WORKSHOP.md) gives the class filter and simulator selection.

| Scenario | Observed behavior |
| --- | --- |
| Fresh reference checkout in a temporary folder | `./gradlew -PsharedReference :shared:testAndroidHostTest :shared:bundleAndroidMainAar` passed without creating a practice source directory. |
| Fresh practice checkout | `:shared:preparePractice` created both missing answers from their templates. The Chapter 19 Android label tests passed. A filtered Chapter 20 simulator run still needed the Chapter 19 label moved to `commonMain` before the tests could compile. |
| Starter planner on Android and the arm64 iOS simulator | Each target ran five planner cases. The inclusive limits and real platform UUID checks passed. Rejection, trimming, and the fallback for a missing or blank topic each failed. |
| Repaired practice planner in a disposable copy | After the Chapter 19 label move, the three label cases passed on each target in isolation. Completing the common planner made the five planner cases pass on both. Running both suites together produced eight passing tests per target. |
| Independent reference | `:shared:testAndroidHostTest` and `:shared:iosSimulatorArm64Test --device "$study_simulator"` passed all eight cases per target with `-PsharedReference`. Both reports had zero failures, errors, and skips. |

Both completed variants built `:shared:bundleAndroidMainAar` and `:shared:linkDebugFrameworkIosSimulatorArm64`. The AAR's `classes.jar` contains the planner, and the simulator framework header exposes the planner, its optional result, the ID source, and the platform factory. The reference also compiled `:shared:compileKotlinIosArm64` for iOS devices. Runtime checks covered the Android host JVM and the arm64 iOS simulator. SwiftUI consumption follows in Chapter 21.

## Boundary and preservation checks

- In a disposable practice answer, moving `ids.nextId()` above the duration guard preserved the correct return values. Exactly one of the five planner tests failed on the Android host, identifying ID requests for rejected durations.
- Changing only the Android actual function's spelling in a separate copy caused `:shared:compileAndroidMain` to report that it had no corresponding expected declaration. The simulator compilation succeeded with its own actual. Restoring the spelling restored the Android build.
- The lesson's `TicketIds` example produced the stated sequence and preserved the call count after a rejected plan. A separate host check also compiled and called the common `Uuid.random()` API with the experimental opt-in on the pinned Kotlin version.
- Repeating preparation and cleaning in the disposable copy preserved edits to both answers and kept the label's old location empty. The real workspace's 22 previous answer files matched their pre-change checksums. Its new planner matches the starter and Git ignores it.
