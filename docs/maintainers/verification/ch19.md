# Chapter 19 verification

Checked locally on 19 November 2026 with JDK 17, Gradle 8.14.3, Kotlin 2.2.21, Android Gradle Plugin 8.11.1, and Android SDK 36. The Apple runs used an Apple silicon Mac, Xcode 27.0 (27A266a), the iOS 27 SDK, and iPhone 17 Pro simulators running iOS 26.5. JetBrains lists Xcode 26.0 for this Kotlin release. The local compiler linked and ran the simulator tests with Xcode 27.0. [Toolchain research](../RESEARCH.md)

## Learner and reference runs

All Gradle commands start in `mobile`. The device argument selects a workshop simulator by UDID.

| Scenario | Command or inspection | Observed result |
| --- | --- | --- |
| Discover the project | `./gradlew projects` and `./gradlew :shared:tasks --all` | Gradle lists the shared module, Android host tests, simulator tests, and simulator framework task. |
| Build without a learner answer | `./gradlew -PsharedReference :shared:testAndroidHostTest :shared:bundleAndroidMainAar` in a fresh copy | Both tasks succeed. The practice directory is still absent. |
| Prepare the starter and test Android | `./gradlew :shared:preparePractice :shared:testAndroidHostTest :shared:bundleAndroidMainAar` | The prepared file matches the template under `androidMain`. All three host tests pass and the AAR builds. |
| Compile the starter tests for iOS | `./gradlew :shared:compileTestKotlinIosSimulatorArm64` | The compiler reports an unresolved `studyLabel` at all three calls in the common tests. Execution stops before any test runs. |
| Move the file to `commonMain` in a disposable copy | `./gradlew :shared:testAndroidHostTest :shared:bundleAndroidMainAar`, then `./gradlew :shared:linkDebugFrameworkIosSimulatorArm64` and `./gradlew :shared:iosSimulatorArm64Test --device "$study_simulator"` | Both artifacts build. The XML reports record three tests and zero failures on each target. |
| Run the worked solution | Run the same artifact and test tasks with `-PsharedReference` | All three cases pass on each target. The native test runner also executes on an explicitly selected shutdown simulator. |

The three cases cover a topic with surrounding spaces, a blank topic with zero minutes, and a negative duration. In both the completed exercise and the reference, the AAR's `classes.jar` contains `workshop/studylab/shared/StudyLabelKt.class`. The generated header in `StudyShared.framework` exposes `studyLabel(topic:minutes:)` to Swift. Its property list identifies the platform as `iPhoneSimulator`.

## Answer preservation and existing app

After moving the practice file in a disposable workspace, adding a learner note and repeating `:shared:preparePractice` preserved the note and kept the old location empty. Running `:shared:clean` also preserved the moved answer. The working tree's 21 earlier learner files matched their pre-change checksums. Its new ignored Chapter 19 answer matched the starter.

The existing Android app built both debug variants and passed all 20 reference unit tests with `./gradlew :androidApp:assemblePracticeDebug :androidApp:assembleReferenceDebug :androidApp:testReferenceDebugUnitTest`. Apple execution covered the arm64 simulator. Physical-device builds and app integration fall outside this exercise.
