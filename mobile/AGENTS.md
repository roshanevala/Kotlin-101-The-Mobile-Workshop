# Mobile workspace guidance

Apply the repository root guidance. This directory contains the Android app, native `iosApp` client and KMP library in `shared`. The rules below cover Android and Gradle. Use `iosApp/AGENTS.md` for the SwiftUI framework consumer, its commands, and source ownership. Keep the independent Kotlin/Swift language labs separate.

- Use the mobile wrapper and catalog for `:shared`. Its Chapter 19 answer can live in `shared/src/practice/androidMain/kotlin` or `shared/src/practice/commonMain/kotlin`. Preserve either location. Chapter 20 adds `shared/src/practice/commonMain/kotlin/SessionPlanner.kt`. Prepare each missing answer independently. Use `-PsharedReference` for independent reference builds. Verify the Android host tests, arm64 simulator tests and both library artifacts when changing shared build wiring.
- Keep AGP 8.11.1, Kotlin/Compose compiler 2.2.21, Gradle 8.14.3, JDK 17, compile/target SDK 36, Build Tools 35.0.0, minimum SDK 30, Compose BOM 2025.10.01, and Activity Compose 1.11.0 unless a later chapter verifies a change.
- Chapter 15 adds Lifecycle 2.9.4, Navigation Compose 2.9.5, and Android/core coroutines 1.11.0 with test-only coroutines-test 1.11.0 and JUnit 4.13.2. Espresso core 3.7.0 remains test-only for API 36. Chapter 21 links the Kotlin reference library into both SwiftUI app schemes. The Android app builds independently.
- Tracked `src/starter` and `src/solution` supply MainActivity (13), StudyPlannerActivity (14), and CatalogueViewModel (15). The ignored `src/practice/kotlin/workshop/studylab` files are learner-owned: never overwrite or stage them. `preparePractice` fills all missing answers; `prepareComposePractice` and `prepareArchitecturePractice` fill only their chapter's missing file. `clean` preserves all three.
- Shared main supplies the fixed CatalogueActivity launcher, repository, state/model, navigation, resources, and window helper; it contains neither older variant Activity nor the learner ViewModel. The old Activities remain internal for retained tests. A growing practice variant compiles all three answers; old compile errors need repair or a separate fresh snapshot folder. Reference never compiles practice sources, and variants install under separate IDs.
- Build both variants with `:androidApp:assemblePracticeDebug :androidApp:assembleReferenceDebug`; run `:androidApp:testReferenceDebugUnitTest` and `:androidApp:lintReferenceDebug`. Device checks use `:androidApp:connectedReferenceDebugAndroidTest` or the practice task. Scope ANDROID_SERIAL when several devices are attached.
- Current counts: 20 local ViewModel/repository tests and 46 device checks (14 architecture/navigation, 22 Compose, ten old lifecycle). Chapter 15 tests use real ViewModelStore cleanup, a replaced/reset Main dispatcher and one scheduler. UI collection is lifecycle-aware; its pause is distinct from cancellation of ViewModel work. Handle-initialization and Activity recreation tests do not independently establish OS process restoration.
- The catalogue uses constructor injection and four explicit states. Cancel obsolete requests, preserve cancellation, snapshot repository lists, and check coroutine activity before success/IO-failure publication. Do not hide programming failures as recoverable errors or retain Activity/View references in the ViewModel.
- The Activity owns the catalogue ViewModel outside NavHost. Navigation carries IDs, with missing-ID recovery. Notes are per-ID saved primitive strings: preserve accepted whitespace, enforce length <=120 and current Content membership, and keep notes separate from reload state. SavedStateHandle must come from owner creation extras; never bundle the catalogue, repository, or Jobs.
- Preserve Chapter 14's six primitive saveable values and transient revision/notice behavior in its existing answers. Keep its controlled editor free of a second authoritative text copy. Do not modify old learner answers to advance the launcher.
- Preserve Chapter 13's disabled automatic widget saving so tests cannot mask missing Bundle logic. Keep empty text valid, read current text when saving, and restore the backing count before rendering. Never promise onDestroy before process termination.
- Use temporary copies for source-isolation, broken-source, and seeded-defect checks. Do not infer learner completion from reference passes. Local SDK paths, signing data, answers, build/bin output, and emulator state stay untracked.
- Published ch13-v1 and ch14-v2 pin older launchers; ch15-v1 pins Chapter 15 with both source variants. Never move published tags. Corrections need a new versioned tag; never link an unpublished tag.
