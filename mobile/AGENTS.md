# Mobile workspace guidance

Apply the repository root guidance. This is the growing Android workspace; keep `kotlin-labs` independent.

- Pin AGP 8.11.1, Kotlin 2.2.21, Gradle 8.14.3, JDK 17, compile/target SDK 36, Build Tools 35.0.0, and minimum SDK 30 until a later chapter makes a verified change.
- Chapter 13's platform Activity/XML remains preserved; Chapter 14 adds Compose with compiler plugin 2.2.21, BOM 2025.10.01 and Activity Compose 1.11.0. Keep ViewModel, storage, KMP, and iOS for their chapters. Espresso core 3.7.0 is pinned only for device-test compatibility with API 36.
- Tracked `androidApp/src/starter` holds the exercise and `src/solution` its reference. `preparePractice` prepares missing `MainActivity.kt` (13) and `StudyPlannerActivity.kt` (14) under ignored `src/practice/kotlin/workshop/studylab`. `prepareComposePractice` prepares only the latter. Treat both as learner-owned; never overwrite or stage them. `clean` must preserve both.
- Shared manifest, resources, window scaffolding, and instrumented acceptance tests live in tracked `src/main` and `src/androidTest`. Neither Activity class is in shared main. The current launcher is StudyPlannerActivity; MainActivity remains internal for old device checks. The growing practice variant compiles both answers; old compile errors must be repaired or isolated by using a fresh checkpoint folder. The practice/reference flavors compile independently and install under different IDs.
- Build with `./gradlew :androidApp:assemblePracticeDebug :androidApp:assembleReferenceDebug`; lint with `:androidApp:lintReferenceDebug`. Reference device checks use `:androidApp:connectedReferenceDebugAndroidTest`; learner checks use `:androidApp:connectedPracticeDebugAndroidTest`. Scope `ANDROID_SERIAL` when multiple devices are attached.
- The 32 instrumented checks include 22 Compose checks and 10 retained ActivityScenario checks. The Compose owner/editor contract and notice timers use semantic queries and the Compose test clock. The old Activity checks use ActivityScenario and require a running API 30+ emulator/device. They establish recreation behavior, not real process death. Check process restoration separately by backgrounding, killing only that app's background process, and reopening its retained task; never equate force-stop with system restoration.
- Chapter 13's automatic widget saving is deliberately disabled for its topic/count mission. Preserve this in both variants so it cannot mask a missing Bundle implementation. Keep empty text valid, read current text when saving, and restore the backing count before rendering.
- Chapter 14 saves six primitive authoritative values; derive immutable two-row models from them. Keep saved revision/notice transient, and never reset restored draft from a selection-keyed effect. Stable list keys/callbacks use IDs, not editable topic names. Keep the controlled editor free of its own authoritative text copy.
- Keep saved state small; do not store Context, View, Activity, or long-lived objects in a Bundle/static singleton. Never promise onDestroy before process termination.
- Use temporary workspace copies for broken-source and seeded-defect checks. Verify neither variant compiles the other's Activity. Do not infer a learner walkthrough from reference passes.
- `local.properties`, signing material, answers, build/bin output, and emulator state stay untracked. Do not place personal SDK paths in documentation.
- Source start/finish checkpoints are the practice template/reference variant. Published `ch13-v1` pins the old source and `ch14-v1` pins Chapter 14 with both variants. Never move a published tag; corrections need a new versioned tag. Do not link a tag before it exists.
